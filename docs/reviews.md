# 聚合评论

`GET /tmdb/{movie|tv}/reviews?id=<TMDB ID>&language=zh-CN&sources=all`

客户端只有在季列表里明确存在 S2（`season_number == 2`）时才使用分季评论；
S0 不计入多季判断，只有 S1 或 S0＋S1 时请求全剧评论。不能仅凭数组长度或出现 S3 判定多季。
多季电视剧可加 `&season=2`：豆瓣、巴哈按所选季匹配并分别缓存；TMDB 保留全剧评论。
App 的 Trakt 请求采用同一规则：单季取全剧，多季取对应季，不根据评论是否为空改变范围。切季会取消旧显示任务、清空上一季列表，
优先读该季本地缓存；迟到的上一季结果不会覆盖当前季。

保留 TMDB 原有响应格式，`results` 追加豆瓣短评和巴哈姆特 ACG 动画作品评价。
Trakt 仍由 App 原有调用加载。省略 `sources=all` 时保持旧行为，避免旧版 App
把新来源误标为 TMDB。

新增评论字段：`source`（`douban` / `bahamut`）、`likes`、`url`；评分在
`author_details.rating`，统一为 0–10。原有 TMDB 评论没有 `source`，客户端默认 TMDB。
全部来源合并后按 `created_at` 从新到旧排列，不使用评分或点赞数排序；
缺失或无效时间的评论排在最后。App 合并 Trakt 评论后继续使用相同排序。

## 响应速度与缓存

- 新版 App 正常先等详情请求返回（命中详情缓存则立即复用），再把同一份资料里的片名、原名、年份、动画类型及所选季信息放在 `context` 参数中请求评论；不提前发送缺资料的占位评论请求，也不为评论额外请求作品资料。缺字段、语言不适合当前来源或匹配不到时，后端才补查 TMDB 的简中/繁中资料；补查在两家来源之间合并复用。
- 客户端参数先校验长度、类型、年份和季号；它的缓存按参数指纹隔离，不覆盖服务端核实过的条目映射。已有常规评论缓存仍优先复用。
- 后端已核实的作品资料随快照保存，后续刷新可省掉重复的 TMDB 资料请求。豆瓣、巴哈的数量和 10 秒等待上限均保持不变。
- TMDB 请求和补充评论读取从请求开始并行执行，豆瓣、巴哈抓取也并行执行。
- 命中评论缓存时直接合并返回；缓存读取的快速路径等待上限为 150ms。
- 没有评论缓存时，补充来源最多等待 10 秒。及时完成的来源合并到当前响应；较慢的来源继续在 Worker `waitUntil` 中补抓，后续请求可见。
- 两家来源各自完成后立即更新进程内缓存，不会因一家较慢而隐藏另一家已经取得的评论。
- 聚合模式中 TMDB（含英文回退）共用 10 秒截止时间，与补充评论并行等待。TMDB 超时或失败时，仍返回已有补充评论；所有来源均不可用时返回错误。网络传输时间不计入服务端等待预算。
- R2 复用现有 `ASSETS` binding，键为 `reviews/v2/{type}/{id}.json`，分季使用 `reviews/v2/tv/{id}/season/{season}.json`；Bun 使用已有 R2 配置。
- 成功匹配的来源一天刷新一次；未匹配六小时后重试；来源失败十五分钟后重试并保留旧评论。
- 不翻页：豆瓣单次请求最多 50 条；巴哈保留首批返回的有效评论（通常最多 30 条），上游按最新排序；Trakt 单次最多 50 条。过滤空内容和剧透后可能更少。App 合并显示上限 150 条。
- 每个 Worker isolate 最多同时补抓 4 部作品/季，合并同作品同一季的并发请求。
- 聚合响应缓存五分钟；没有新增评论时缓存三十秒。进程内快照最多保留 128 部作品。
- App 的非空评论列表仍缓存六小时，空列表仅缓存三十秒，避免临时失败长时间隐藏评论。

## 匹配与范围

后台读取 TMDB 简中、繁中和原名。豆瓣要求标题、年份、电影/电视剧类型一致；
第一季允许无季号剧名；后续季使用该季首播年份和带季号的标题或 TMDB 季名匹配，不回退到其他季。中文与阿拉伯数字季号等价。特别篇不猜测豆瓣/巴哈映射，只保留 TMDB 全剧评论及 Trakt 特别篇评论。
巴哈只为动画作品查询，优先使用免登录的 JSON 链路：
`mobile_app/anime/v1/search.php` → `anime/v1/video.php` → `acg/v1/reviews_list.php`。
搜索按标题和年份匹配，视频资料再次核对 ACG ID、视频 ID、标题和首播年份，再使用 `fanId` 读取公开评价。
动画瘋未收录或 JSON 接口不可用时，回退到原来的 ACG 搜索页、作品页验证流程。
已有 `fanId` 的作品仍然直接读取评价，无需重复匹配。
匹配不唯一、来源验证失败或反爬拦截时不引入不确定的评论。

这不是动画瘋弹幕或哈啦板讨论串的抓取，也不承诺完整评论历史。
内部网页接口可能变化；新增来源故障不会阻塞原有评论，缓存中的旧评价继续可用。


测试覆盖来源解析、季与年份防错配、冷/热缓存、并发合并、存储延迟上限、
单来源失败保留数据、并行请求、首次合并、等待超时和旧版接口兼容。App 端通过共用解码层识别新来源，豆瓣、巴哈不显示来源标记。
